# Glossary

*Agents use these terms and no synonyms for them. Every term is proposed until the names are settled (Q1 in [[Open questions]]).*

| Term | Meaning |
| --- | --- |
| *Plane* | *One of two sets of documents: intents and plans, or specs and near-code docs. See [[Method#Two planes]].* |
| *Level* | *Position inside a plane: level 1 is closer to ideas, level 2 closer to code.* |
| *Intent* | *An idea, proposal, roadmap item or open question.* |
| *Plan* | *Instructions for one task: the user prompt plus references to specs.* |
| *Spec* | *An architecture page describing the system.* |
| *Near-code doc* | *A document close to code: natural-language tests, dependency files, declarations, models, generated docs.* |
| *Projection* | *A near-code doc generated from code or configs by a script. See [[Review#Level 2 projections]].* |
| *One-pager* | *A page that fits on one A4 sheet at 12 pt, ideally with an image.* |
| *Page format* | *A template from the curated list in [[Method#Page formats]].* |
| *Do and throw* | *Implementing a draft to test a spec, then discarding the implementation.* |
| *Frontier model* | *The expensive model that runs the workflow and writes documents.* |
| *Cheap model* | *The inexpensive model that implements; its one-pass success tests the specs.* |
| *Review vault* | *The single folder with every document for review.* |
| *Review mark* | *Formatting that records the review state of text. See [[Review#Review marks]].* |
| *Exclusion field* | *The `exclude` property: what a page should not contain.* |
